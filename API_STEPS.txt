To help you understand how the system works from start to finish, here is the **Full End-to-End API Workflow**. 

This sequence follows the lifecycle of an insurance policy, from user creation to claim approval.

---

### Phase 1: User Management (Admin Setup)
*The system starts with an Admin setting up the participants.*

1.  **POST `/auth/login` (Admin)**: Log in with Admin credentials to get a token.
2.  **POST `/auth/register` (Admin)**: Register a new **Agent**.
3.  **POST `/auth/register` (Admin)**: Register a new **Customer**.

---

### Phase 2: Quote Generation (Agent Action)
*An Agent prepares a pricing quote for the new Customer.*

4.  **POST `/auth/login` (Agent)**: Log in with Agent credentials.
5.  **POST `/quotes` (Agent)**: Create a new Quote for the Customer (Status is `draft` by default).
6.  **PUT `/quotes/{id}` (Agent)**: Update the quote to change status to `submitted` (Sending it to Admin for review).

---

### Phase 3: Policy Approval (Admin Action)
*The Admin reviews the submitted quote and activates the policy.*

7.  **PUT `/quotes/{id}` (Admin)**: Change the quote status to `approved`. 
    > **Note**: A Quote must be `approved` before any claims can be filed.

---

### Phase 4: Filing a Claim (Customer Action)
*An incident occurs, and the Customer files a claim against their active policy.*

8.  **POST `/auth/login` (Customer)**: Log in with Customer credentials.
9.  **GET `/quotes` (Customer)**: View their approved quote ID.
10. **POST `/claims` (Customer)**: Create a Claim using their `quote_id`. 
    > **System Rule**: This will fail if the quote is still in `draft` or `submitted`.

---

### Phase 5: Claim Settlement (Agent/Admin Action)
*The company processes the claim.*

11. **GET `/claims` (Agent)**: List all claims requiring attention.
12. **PATCH `/claims/{id}/status` (Agent/Admin)**: Update the claim status (e.g., to `Under Review`, `Approved`, or `Rejected`).

---

### Phase 6: Audit & Profile (General)
*Ongoing monitoring and management.*

13. **GET `/activity-logs` (Admin)**: Review the history of who did what in the system.
14. **GET `/auth/profile` (Any)**: Check the currently logged-in user's details.
15. **POST `/auth/logout` (Any)**: Securely exit the system.

---

### Testing Tips for Postman:
*   **Sequential IDs**: As you create a Quote, note down the `id` returned in the JSON response. You will need it for the Claim creation step.
*   **Token Management**: Every time you switch roles (Admin to Agent, etc.), you **must** update the `Bearer Token` in your Postman Authorization tab.
